# API Contracts

Public module interfaces are declared in Swift protocols and public value types. This document describes the cross-module contracts.

Current implementation: **1.0.8/build 9 locally validated**. Build/test, active-engine helper rejection, selected-engine normal exit and exact local app launch/refresh receipts are recorded in `VISUAL_EFFECTS_VALIDATION.md`; they do not establish physical effects/readiness or restoration.

## External Kinetiq engine (experimental opt-in)

The 5 November user contract authorizes private AX mapping, event-tap/click replay and off-screen parking in the real, separately installed Kinetiq.app. These techniques stay optional/disabled by default in AETHER, not required by its stable public-API path. The sections below describe **AETHER-owned** native/capture/preview/rendering/effect APIs, not contracts automatically imposed on Kinetiq. See `KINETIQ_ENGINE.md`.

`@MainActor KinetiqEngineCoordinator` exposes passive `applicationCandidates`, `validateApplication(at:)` and `refreshStatus()`, explicit async `start(applicationURL:experimentalConsent:)` and `stop()`, observable metadata/process/error state, `isLaunchPending` and conservative `isActive`. Metadata includes canonical application/executable URLs and actual version/build. Validation checks expected identity and effects resources without loading code; it is not authentication/signature verification.

Start requires consent and a trusted selected bundle. It connects only to one exact bundle/executable match or explicitly asks `NSWorkspace` to launch it; conflicting/multiple instances fail. Start/Stop waits have **10-second operation deadlines**. Cancellation/timeout does not revoke an issued OS launch/quit. Pending launch ownership blocks replacement; late callbacks retain matching app handles. Stop validates the selected process identity and requests **normal `NSRunningApplication.terminate()` only**, never forced termination; refused/timed-out/cancelled outcomes retain uncertainty for retry. Passive refresh never takes control of an independent instance.

`isRunning` means process existence, not Accessibility/Recording grant, event-tap readiness or working shaders. There is **no IPC/RPC** for readiness, capture, effect choice or settings. Kinetiq's own permissions/settings apply; its raise-time prefetch/recapture is not AETHER's one-image/1600px/bounded-preview policy. AETHER exclusions and Reduce Motion do not automatically apply. Page dismissal/AETHER quit does not terminate Kinetiq. Normal external cleanup aims to restore parked native windows; a PID exit is not restoration proof.

RuntimeModel admission rejects AETHER focus/move/capture/effects while Kinetiq is running, starting/stopping or unresolved, including independent instances; passive refresh remains allowed. It rechecks after configuration await; visible panels observe every **500ms**, without autostart. Final **7/7 XCTest** verifies the actual model's six command rejections, passive refresh and unchanged fixture geometry/visibility; test-only Interface linkage creates no production Core cycle. This is **not a cross-process IPC lock**: independently starting an engine during already-in-flight work is not atomically prevented. Finish/cancel AETHER operations before any external launch. Late/refused-quit timing remains manual/source review. `WindowEffectCoordinator` below is the separate diagnostic fallback, **not Kinetiq**.

The build/effect/capture/window helpers additionally reject an observed running Kinetiq with **exit 2** before any operation starts. All four were invoked against the real trusted-path bundle and explicitly requested quit/stop Kinetiq; the enclosing check returned **`HELPER_GUARDS_EXIT0`**. This preflight is not an atomic inter-process lock. The selected identity-checked `NSRunningApplication` subsequently exited after normal `terminate()`, without forced kill; this does not certify restoration.

## Window discovery/control
Discovery produces snapshots with capabilities. Control methods must verify results and return typed failures. Discovery must not imply control capability.

`WindowCapabilities.canClose` is true only after a public AX probe finds the selected window's close button, verifies the owning PID, enabled state and advertised `AXPress` action. It defaults to **false** on initialization and when older Codable records omit the field; malformed types still fail decoding. This is a supported request capability, not a promise the app will accept closure.

`NativeWindowService.close(_:)` takes a registered `RuntimeWindowHandle`, not a bare CG ID. It serializes same-window mutations, revalidates generation, AX membership/correlation and process launch identity, then reacquires/reprobes the enabled close button before a **single** `AXUIElementPerformAction(..., kAXPressAction)`. Preparation has a 2s deadline with existing bounded AX IPC; verification has a separate **2s** deadline. Success requires exact ID/PID disappearance from `CGWindowListCopyWindowInfo(.optionAll, kCGNullWindowID)`, without visibility, layer, title or geometry filtering. Off-screen, hidden or minimized is not closed; failed/incomplete inventory and reused identity are errors, never success.

Pre-press cancellation sends no close. After AXPress is attempted, cancellation, timeout, refusal/save-sheet or verification failure returns **`NativeWindowCloseError.outcomeUnconfirmed(reason:)`**: a request may still complete. Do not retry automatically, animate as if closed, hide the native window or claim rollback. An AX success code alone is not closure proof. `isWindowClosed(_:)` is read-only and requires this service's exact closure receipt (latest 128 retained); it checks process identity and the full CG inventory again, rejecting unknown/forged generations and reused IDs/PIDs. AX objects remain actor-owned.

## Capture
Capture is owned by the capture actor. Consumers receive immutable frame metadata and copied BGRA `Data` (at most 1600px per edge), never SDK objects. `captureSnapshot(request:)` takes one image through Apple's public [SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager) `captureImage` API; it creates no `SCStream` and has no screenshot refresh loop. `startCapture(request:)` explicitly selects continuous stream delivery. Both require a validated runtime handle and caller revalidation before/after asynchronous capture.

The concrete owner admits **one mutually exclusive snapshot or stream lease**, including startup and unconfirmed cleanup. Concurrent capture rejects additional ownership. Screenshot waiting has a 5s deadline; cleanup has an independent 3s deadline that does not inherit caller cancellation. Stop settles the Swift waiter, not the non-cancellable SDK enumeration/image callbacks: callback ownership and resources remain retained until actual completion, even after timeout. Unconfirmed cleanup blocks replacement until retry confirms release. On success, screenshot SDK inputs and the snapshot lease are released before the copied frame reaches static Metal presentation.

For live streams, Stop likewise settles pending startup and independently awaits confirmed SDK teardown; Start rechecks ownership/activity after suspension. These contracts do not guarantee that SDK callbacks return. Tests observe internal session IDs without exposing SDK objects, titles or pixels. Screen Recording remains required in both modes; no private flags, indicator suppression or permission bypass is used, and absence of macOS indicators is not guaranteed.

## Diagnostic preview
`WindowPreviewCoordinator.preview(..., mode: .snapshot)` is the default. **Snapshot 5s** presents one captured image: receipt-age freshness is checked only before its first presentation (at most 1s old). Its retained texture is intentionally static for at most 5s, not a source of refreshed content; existing permission/secure-input and native identity/geometry monitors remain active. **Live diagnostic** explicitly uses continuous 30fps `SCStream` delivery, with OS recording indicators expected. Live still requires its first complete frame within 2s and checks freshness for every handoff. Both preserve the native window and remove the overlay on interruption/cancellation.

For a successful snapshot, `framesPresented == 1` means one GPU-completed submission, not physical scanout or proof that the displayed content stayed fresh. GPU resources remain owned until actual command completion even after the 750ms presentation deadline. Neither mode certifies physical platform behavior or implements M3 animation.

Both modes check passive Recording/secure-input state and `CGWindowListCopyWindowInfo(.optionIncludingWindow)` every 100ms. Visibility requires exactly one matching CG ID/PID/on-screen row before AX IPC, without replacing generation/geometry checks. After caller validation, periodic AX begins 500ms after monitor start and repeats every 500ms plus IPC latency. This addresses the historical post-GPU AX/minimize race; CG-only still failed. Timeouts remain failures, budgets unchanged, no SDK delays injected. Historical 1.0.7 evidence stays in `M2_VALIDATION.md`; current 1.0.8 capture passes **22 functions / 26 cases**, two denial skips, **21.408s** (`/tmp/aether-kinetiq-final-capture.log`, exit 0). Physical/platform checks remain pending.

## Rendering
Render commands are values. GPU objects remain owned by the renderer. Renderer initialization, suspension and shutdown are explicit lifecycle operations.

`MetalOverlayPresenter.prepareEffect(_:frame:relativeTo:)` validates/uploads one immutable BGRA snapshot while the panel stays hidden. `renderEffect(vertices:opacity:dissolve:)` reuses that texture without recapture/reupload. `OverlayVertex` is a position/UV value; the bounded complete-triangle list is validated before GPU allocation. The effect-only `relativeTo: 0` supports normal front ordering after verified native closure, not a native-window identity; ordinary preview still requires a positive target number.

At most **one GPU submission** is in flight; this does not mean only one frame per animation. The **750ms** completion wait bounds control flow, not GPU execution. Prepared texture is cached until removal/replacement/failure; any in-flight texture, vertex buffer, drawable and command buffer remain owned until the actual completion callback, even after timeout/cancellation/remove. Removal is immediate/idempotent. Panels cannot become key/main and ignore mouse input; they are not interactive replacement windows. `framesPresented` counts GPU completions, not physical scanout or measured fps; texture bytes are estimated.

## Effects
Effects declare ID, category, triggers, parameter schema, capture/3D requirements and performance class. Unknown effect IDs fail validation.

### Explicit manual coordinator (1.0.8/build 9 development slice)
`WindowEffectCoordinator.perform(_:on:configuration:duration:)` accepts `.wobble` or `.dissolveClose`. `WindowEffectReport` returns kind, GPU-completed count, removal, confirmed close and reduced-motion selection. One transaction per coordinator, UI serialization. Final real effects regression passes **6 functions / 7 cases**, zero skips, **9.880s** (`/tmp/aether-kinetiq-final-effects.log`, exit 0); this is not full M3/M4, visual acceptance or generic registry implementation (`DeclarativeEffect` remains no-op/planned).

Both kinds revalidate the handle before/after one selected-window `SCScreenshotManager.captureImage` snapshot, then upload once. They reuse Capture's permission/privacy exclusions, 5s wait, independent 3s cleanup, non-cancellable callback lifetime and no-SCStream policy. Snapshot lease is released before rendering. Initial receipt age must be at most 1s; close additionally rejects a snapshot older than 3s after confirmed native close (closure cannot be undone if that check fails).

- **`.wobble`**: UI duration 2s; independent 17 × 13 displacement lattice at fixed 120Hz steps, with fixed impulse rather than global input/drag sampling. Original stays visible, interactive and geometrically unchanged. During animation, permission/secure input and exact CG ID/PID/on-screen/frame checks run each iteration; AX generation/geometry revalidation begins after 500ms and repeats at that interval plus IPC latency. Native changes interrupt/remove the overlay without restoring over user actions.
- **`.dissolveClose`**: UI duration 1.1s. Prepare texture/panel hidden, request `close(_:)`, and **only after confirmed full-inventory disappearance** animate the original procedural dissolve. Recheck `isWindowClosed(_:)` during and after animation. A close failure does not display an overlay or trigger an automatic retry. Confirmation is supplied by the UI; direct API callers are responsible for explicit destructive intent. This is not universal red-button/Cmd-W interception.
- **Motion/timing**: API defaults to 2s and accepts 0.2...3s animation durations; capture/AX/cleanup deadlines are separate, so 3s is not a total transaction deadline. `ContinuousClock` drives progress with approximately 16.67ms/60fps target pacing; slow work never queues a frame backlog. No achieved fps/latency claim is made. System **OR** configuration Reduce Motion replaces deformation/noise with a fade.
- **Cancellation/failure**: `removeOverlay()` removes visuals and requests stop; the owning structured task must also be cancelled (UI Stop/Escape/navigation does both). Preserve typed unconfirmed-close outcomes. If close was attempted/completed before another failure, inspect native state; Stop cannot undo it. This AETHER-owned diagnostic performs no rollback/native hiding/off-screen parking; external Kinetiq's experimental parking is a separate authorized path. Capture cleanup errors retain ownership and report failure rather than a false pass.

## Animation
Timeline times are monotonic offsets in seconds. Progress is clamped. Cancellation must invoke cleanup. Completion behavior is explicit.

## Persistence
All writes are transactional. Migrations are numbered, tested and backed up before destructive schema changes.
