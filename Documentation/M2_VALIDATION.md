## Implemented boundaries

- `WindowPreviewCoordinator` revalidates the session-scoped native handle before and after asynchronous capture. It does not move, hide, resize or focus the native window.
- `WindowSnapshotLease` confines screenshot SDK references to its serial owner queue, copies the image into immutable BGRA `Data` (maximum edge 1600px), and releases successful screenshot inputs and lease ownership **before** static Metal presentation. The image timestamp represents receipt uptime, not a source presentation timestamp.
- Snapshot waiting has a 5s deadline; cleanup has an independent 3s deadline that ignores parent cancellation. Stop settles the Swift waiter, not non-cancellable enumeration/image SDK callbacks. Callback ownership/resources remain retained until actual completion, even after timeout; unconfirmed cleanup blocks snapshot **and** stream replacement. Late enumeration cannot start a screenshot after cancellation wins admission. See `API_CONTRACTS.md` for the shared single-lease contract.
- Explicit Live diagnostic uses `CaptureStreamLease`: maximum edge 1600px, 30fps, queue depth 3, newest-only async buffering of 1, no cursor/audio/shadows. Stream startup/cleanup retain the independent 5s/3s deadlines and ownership recheck after suspension. Both paths are CPU-copy based, not zero-copy or 60/120fps performance claims.
- Known credential bundle families and configured exclusions are denied; secure input and passive Recording checks guard startup and delivery. The denylist is not exhaustive and cannot identify every protected surface. Add other bundle IDs to `captureExcludedBundleIDs` and restart after configuration edits.
- Snapshot freshness is checked only before the first presentation (receipt age at most 1s); the retained texture is intentionally static for at most 5s, not refreshed or rejected merely for aging during that hold. Live requires its first frame within 2s and rejects each handoff older than 1s. Both modes check permission/secure input and exact CG ID/PID/on-screen visibility every 100ms before AX IPC. Callers validate after capture/before presentation; periodic AX identity/frame validation starts 500ms after monitor start and continues every 500ms plus bounded AX IPC latency, without an immediate duplicate. Moving, resizing, minimizing or losing the target aborts; no rollback overwrites native actions.
- The temporary Metal panel is non-activating, input-transparent and ordered relative to the selected native window at normal level. Display coordinates use points and actual backing scale; drawable edge is capped at 3200px.
- GPU work is serialized. A 750ms completion deadline closes a failed presentation, but GPU resources remain owned until actual completion. Removal invalidates the transaction immediately and is idempotent.
- Successful snapshot `framesPresented == 1` counts one GPU-completed submission, not physical scanout or ongoing content freshness. Texture-byte diagnostics estimate owned textures, not total GPU memory. Static diagnostic preview is not the M3 motion engine.

### Public-API comparison, not source adoption

At pinned Wobbly commit `84147639eb5b285bca75c63ccabfde9a88ad5cfa`, [`Sources/Wobbly/WindowCapture.swift`](https://github.com/jsgrrchg/Wobbly/blob/84147639eb5b285bca75c63ccabfde9a88ad5cfa/Sources/Wobbly/WindowCapture.swift) uses one-shot `SCScreenshotManager.captureSampleBuffer` calls, not continuous `SCStream` capture. AETHER independently uses `captureImage` for its normal snapshot path; Apple documents both in [SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager) (macOS 14+). This is a public-API design comparison only: no GPL source was copied, and neither Wobbly's launch warmup capture nor off-screen native-window parking was adopted. AETHER never starts capture at launch and keeps the original window visible/authoritative. Public screenshot APIs still require consent and do not establish an unconditional absence-of-indicators guarantee.
